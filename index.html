        📘 Comment ça marche ?
        
  
          
   
        1. Besoin : on part d'un problème réel, celui des élèves ou de l'enseignant, et d'un critère de réussite observable.
          2. 
   
        2. Conception : on choisit qui utilise l'appli, quand, sur quel appareil, avec quelles données.
          3. 
   
        3. Claude : la Fabrique rédige un cahier des charges complet (prompt) et prépare un kit de démarrage. Claude code l'appli et vous rend un .zip.
          4. 
   
        4. GitHub : la Fabrique crée le dépôt, y dépose les fichiers et active GitHub Pages. L'appli a son adresse web et s'installe comme une appli.
          5. 
   
        5. Vérifier : contrôle automatique, test avec le critère de réussite, puis intégration au portail Mes Apps EPS ou Applis EPS Élèves.
          6. 
  
        
 
        🔒 Données élèves et RGPD
        
  
        Les applis créées stockent les données uniquement sur l'appareil (base locale du navigateur), comme Mes Apps EPS. GitHub n'héberge que le code, jamais de liste d'élèves : la Fabrique bloque les fichiers de données et ajoute un .gitignore protecteur.
        
  
        Une appli publiée sur un autre compte GitHub (autre adresse xxx.github.io) ne partage pas la base locale du portail : elle échange alors les données par fichier .xlsx (import de la liste, export des saisies), ce que le cahier des charges impose toujours.
        
 
        🧑‍💻 Voie avancée : Claude Code
        
  
        Si vous utilisez Claude Code relié à votre compte GitHub, choisissez cette voie à l'étape 3 : Claude crée lui-même le dépôt, y écrit les fichiers et active GitHub Pages. Les étapes 4 et 5 de la Fabrique servent alors à vérifier le résultat.
